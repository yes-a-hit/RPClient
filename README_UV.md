# RPClient UV（Unoffical Version）

本仓库是 [KafuuNeko/RPClient](https://github.com/KafuuNeko/RPClient) 的非官方定制分支。
上游的中英文说明保持原样不动，这个文件只记录本分支做了什么、怎么构建、有什么边界。

## 与上游的差别

### 品牌与打包

- 应用显示名：`RPClient UV`，`applicationId` 为 `me.kafuuneko.rpclient.uv`，可与上游版本共存安装。
- 关于页新增「定制版版本」，格式为 `UV <定制版号> · 上游 <上游版本>`，一眼能分辨装的是哪一份。
- 签名与维护：`yes a hit`。

### 语言

默认界面语言固定为简体中文，不跟随系统语言；其余 12 个语言目录保持与上游同步。

### 剧本系统（本分支新增）

- 剧本以 JSON 描述：场景、条件、检查点、多入口、解锁关系、角色白名单与禁止名单、
  时间轴（轮次上限，0 为不限）、GM 与骰子开关；上层支持剧本集。
- 格式规范见 [doc/剧本格式.md](doc/剧本格式.md)。
- 编排为表格化：点选链接建立后继与解锁关系，场景可改名、设轮次、设开场、设为入口、删除。
- 运行时判定：关键词、正则、轮次上限；**先判失败后判通关**，
  通关后按剧本设置转入自由模式。判定不交给模型解释，保证同一段对话可复现结局。

### 小说导入

整本 TXT/Markdown 自动分章，支持多文件散装章节。序号识别覆盖中文数字（`第十二章`）、
阿拉伯数字（`7`）、小数（`1.5`）、裸数字前缀（`003`）；散装文件按序号数值排序，
`第X卷` / `Volume N` 自动分卷并归卷。导入后可按需调用模型提取角色卡与世界书。

### 助手

独立的沙箱助手页：文件、角色卡、世界书、剧本四类工具，沙箱限定为应用私有目录。
支持把图片（多模态）与文本作为附件随消息发送。

### 计费

消耗统计页除 Token 外增加余额查询与金额估算：内置常见模型的 CNY 分档价，
按请求时段与模型匹配计价；无内置价的模型回退到 OpenRouter 美元价 × 可配置汇率。

## 开发进度

状态含义：**可用** = 实机跑通过；**受限** = 能用但依赖外部条件；**WIP** = 界面已留位、功能未通。

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 剧本 JSON 导入与校验 | 可用 | 含孤岛场景、死循环、角色名单冲突的拒绝规则 |
| 主线 / 循环 / 自由模式判定 | 可用 | 关键词、正则、轮次上限，先判失败后判通关 |
| 失败与通关提示 | 可用 | 结束时给「重开本场」「离开」两个出口 |
| 推荐行动（选项块） | 受限 | 解析已容错模型漏写闭合标记；模型是否输出取决于提示词遵守度 |
| 旁白与角色分段 | 受限 | 解析器已就位，角色头像回查角色卡；依赖模型按 `【旁白】/【角色名】` 分段 |

| 剧本转场 | 可用 | 通关一章自动进下一章；转场时压缩旧对白，只留场景轨迹 |
| 检查点回滚 | 可用 | 进入 `checkpoint` 场景时存快照，顶栏可退回 |

| 助手图片附件 | 受限 | 图片会编码成多模态块发出；模型不支持视觉时会返回 400，报错写入对话记录 |

| 小说导入与分卷 | 可用 | 中文数字、小数、裸数字前缀；按卷标题自动归卷 |

### 规划中（Coming Soon）

以下为已明确设计、尚未实现的引擎能力。应用内剧本编辑器顶部有对应提示，
避免玩家以为功能缺失是 bug。

**一、局内事件判定**（已实现）

场景 `events` 列表，每条可配触发条件、轮次、对在场名单的增删、
强制目标场景与插入旁白。允许把名单清到**零角色**，此时只与旁白互动。

写法见下方「事件配置」。

**二、自由模式**（部分实现）

`ScriptMode.Free` 的剧本现在会列出所有已解锁场景供自由切换，
不再只走主线后继。场景用 `unlockCondition` 控制开放，条件靠剧本变量判定。

仍未做：角色按时间与地点自行出现。现在进场名单由场景 cast 与事件决定。

**三、文字版 FNAF 示范剧本**

保安在保安室，五天五个场景，每天出动的角色不同、行动方式不同，
玩家要在有限信息下做决策。接入 LLM 后玩法比原作更活。
被抓不只弹出结束提示，而是触发一段战败剧情。

定位是**复杂剧本的示范样本**，用来验证：多日循环、角色行为差异、
条件组合判定、失败演出。

**四、日常模式**

多个场景，角色按固定作息活动，带日历与时间轴。
没有主线但遵循规则，玩家自由选择时间地点行动、与 NPC 互动。

需要：时间轴推进机制、角色日程表、场景开放时段。

**五、NPC 组与子 NPC**

一个角色可挂多个「组」，每组含两个子角色卡（日常形态 / 转化形态），
各自独立头像与人设。支持：

- **临时切换**：形态变化时切到另一组，恢复后切回
- **永久切换**：经历关键剧情后整体换组，日常形态的性格随之改变
- **单组永久改变**：只改人设不改身份，用于表现角色的成长或转折

示例：同一角色分「初始组」与「转化组」，各含日常与变化两个子卡，
两组的性格设定相反（原本冷淡转为热络）。

需要：角色卡关联组结构、切换时的头像与人设替换、切换状态写入存档。

### 变量与开放剧本

剧本声明数值变量后，玩家行为就有了累积后果。条件、场景解锁、事件副作用
都能引用它们，剧本从「写死的分支」变成「按状态涌出走向」。

```json
{
  "variables": [
    { "name": "信任", "initial": 0, "min": 0, "max": 10, "visible": true }
  ],
  "scenes": [
    {
      "id": "roof",
      "name": "天台",
      "unlockCondition": { "type": "Variable", "variable": "信任", "threshold": 5 }
    }
  ]
}
```

- `unlockCondition` **只在自由模式生效**；主线推进不看它，避免条件写错把主线卡死
- 事件用 `effects` 改变量：`{"variable":"信任","delta":2}`，写 `setTo` 则直接赋值
- 变量按 `min`/`max` 钳制，好感冲到 999 会让后续阈值判定全部失效
- 失败与通关条件也支持 `{"type":"Variable","variable":"疑心","threshold":8}`

随机事件加 `"chance": 60`（百分比）。判定走注入的随机源，
测试里传固定种子就能复现同一场，出问题能重放。

`mode` 为 `Free` 的剧本**不做链式可达校验**——它本来就不靠链接推进。
主线剧本仍要求每个场景从入口可达，带 `unlockCondition` 的场景除外。

参考样本见 `samples/demo-open-house.json`。

### 战败场景与惩罚演出

失败不再只有一行红字。给失败条件写 `failSceneId`，命中后先演一段惩罚，
演完再收官——不同来源可以指向不同场景，各角色有自己的收场方式。

```json
{
  "failConditions": [
    {
      "type": "Variable",
      "variable": "电量",
      "threshold": 0,
      "description": "断电了",
      "failSceneId": "punish_bear"
    },
    {
      "type": "Keyword",
      "pattern": "去厨房",
      "description": "你不该离开值班室",
      "failSceneId": "punish_chicken"
    }
  ]
}
```

惩罚场景本身是普通场景，靠事件累加变量、靠 `completionCondition` 收尾：

- **不接 `nextSceneIds`** → 惩罚达标即结束整局，这就是「演完才 Game Over」
- 事件写 `"once": false` 可以让玩家反复出力（摇曲柄、做披萨、表演）
- 惩罚场景里通常不写 `failConditions`，免得再被判死一次

结束界面给三个出口：**重开本场**、**回滚检查点**（有快照时出现）、**离开**。
离开相当于离职，存档保留可重看。

完整示范见 `samples/demo-night-shift.json`：三只玩偶各有各的惩罚——
熊爷要你摇曲柄充能，鸡姐要你做够披萨，老兔要你演到它满意。

### 条件到场

场景的 `cast` 是常驻名单，`conditionalCast` 是按状态决定来不来的角色：

```json
{
  "cast": [ { "name": "老陈" } ],
  "conditionalCast": [
    {
      "name": "苏眠",
      "description": "怕生的翻译",
      "condition": { "type": "Variable", "variable": "信任", "threshold": 3 }
    }
  ]
}
```

- 条件与变量、关键词、轮次通用；不写 `condition` 就总是到场
- `bannedCast` 优先级最高，禁止的人即使条件满足也不会出现
- 结果为空是合法状态：零角色场景只剩旁白
- 三方合成后的名单同时用于 Prompt 与界面头像

意义是**同一场景不必为每种进度抄一份**。公寓走廊在信任不够时只有你自己，
攒够信任后邻居才会出来探头——一份场景跟着状态动。

### 已知问题
- 冒险页「继续冒险」只列进行中的局，已结束的收进可折叠分组。
- 首页筛选栏改为换行排布，窄屏也能一眼看全。
- 剧本生成完全依赖模型自觉：`cast`、`bannedCast`、`failConditions` 等字段若模型不填，
  运行时只能按空名单处理。校验层只能拦住结构错误，拦不住「填了但没意义」。
- 模型漏写选项块闭合标记 `>>>` 已容错，但完全不输出选项块时不会自动补。
- 助手会自行截断，且助手页面缺乏编辑，重生成和导出，也缺乏一个单独的按钮“抽”助手的鞭子，也不能展开助手的思维链，建议移植成熟单会话的功能
- 计费不靠谱,有时不能正确拉取价目并自动计价
- 需要反复鞭策才能概率有效写入，需要进一步进行提示词工程
- 没法导入和读取skill，手动导入没法识别，自动会导入失败
- 助手创作角色卡时，没法写入新增的非官方栏目如恋爱经验，喜好厌恶等
- 缺乏对应的template in json，尤其是新增的栏目
- 新增的大功能 剧本和冒险 需要进一步优化才能游玩

## 构建

前置条件：JDK 17、Android SDK（`compileSdk` 36.1、`minSdk` 26）。

```bash
# 本地
./gradlew assembleDebug testDebugUnitTest

# 产物发布到 dist 并带版本号命名
pwsh -File tools/publish-apk.ps1 -Install
```

推送 `master` 会自动触发 CI：跑单元测试、构建 debug 包，
并以 `v<定制版号>` 为标签发布到 Releases，产物名形如
`rpclient-2026.3.1-dev-debug-v0.17.apk`。

## 边界与免责

- 这是 debug 签名的个人定制分支，**不适合直接上架分发**。
- 剧本、助手等新增功能需要自行配置模型服务；本仓库不含任何密钥。
- 与上游的合并策略：上游文件尽量保持原样，只在必要处做最小改动，
  以便持续同步上游更新。
